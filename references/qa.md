# 出图验收

实现：`scripts/stylebook/qa/`。判定由脚本做，模型只负责「如实转述看到了什么」。

叠字与混合文字仍严格比对标点、内部空格、数字、大小写及重复次数。看图转录可能按可见行拆分，而清单按独立文字块保存；程序只允许移除换行、保序合并相邻转录行，不把版面换行误报成缺字。空转录、错字、额外文字、漏字和非相邻拼接仍拒绝。文字框、字号与实际裁切另走原版式及像素检查，文字比对通过不能代替这些检查。

看图验收对照的是本次清单，不会自行补读整篇文章。文章来源即使只出一张，也先用 `planning.md` 对照全文定位置与信息价值；把不能丢的题材事实写入 `points`，尤其是人物场景。漏写在清单里的事实，单张 `qa` 无法凭空发现。

## 报告对应的输入

`sb.py qa` 的新报告含 `binding`：绑定实际图片、清单、合同文件、方形裁切与缩略图（如适用），以及应有文字、文字模式、格式和判断参数。`plan-review` 绑定完整原文与计划。调用前后输入发生变化时拒绝写出报告。后续消费者可用 `stylebook.qa.binding.verify` 对当前输入核验；旧报告缺绑定会被该函数拒绝，不能事后补哈希冒充当时已绑定。

绑定只证明文件版本一致。使用 `--review-json` 时同时绑定外部结论文件，并标明 `review_mode=supplied`；这不证明结论独立或正确。批量缓存、写作发布及历史报告尚未全部接入此校验，不可据单张 CLI 报告宣称整条发布链完成。

单图核对可见内容，整组核对跨图顺序及角色、场景、道具连续性；精确尺寸和比例读取实际图像量测。看图结论不能代替量测，单张绿灯也不能代替整组检查。必要信息写成无法从单张证明的来源、时间先后或创作用意时，先核对表达方式与检查范围；保留原失败报告，单图改为可观察要点，原文核心关系仍须在文字、结构图或整组检查中验证，不能直接删除。

确需澄清验收清单而未重新生图时，另存 QA 专用修订与原因，再对实际图复核；原生图清单、编译提示词和实际调用记录保留，不将验收修订冒充当时的生图提示词。尺寸证据也须绑定实际文件。

## 六道检查

1. **像素（确定性）**：平均明度、暗部占比、留白、平均饱和度，对照合同 `qa.pixel` 阈值。阈值要用真实出图回测后再定（例：一种暖白黏土样式的阈值用 69 张已发布的真实配图回测，全部通过）。非透明画面另检查原图的透明像素，哪怕只有 1 个也拒绝；显式透明格式保留透明通道。正式批量与单张 `qa --format sticker-single` 均检查 512×512 RGBA、可见主体、四边至少 10% 透明留白和唯一主体连通块；`sticker-grid` 至少要有完全透明背景和清晰可见的主体，宫格切片仍需另走 `sticker-split`。导出非透明格式时同样先检查源图，不能直接把 RGBA 转成 RGB 掩盖边角异常。
   暖色纸底样式可选 `qa.paper_margin_min`，预检黑色墨线和明显色块距画布四边的比例；空图直接拒绝。同一样式的无字场景与有字卡片需要不同纸边时，可在 `qa.paper_margin_min_by_text_mode` 为 `none`、`native`、`overlay` 或 `hybrid` 单独设阈值，未列的模式沿用通用阈值。它只检查可检测的标记，浅色细节、画面是否真正疏朗及手机尺寸可读性仍须看图。不要把全页明亮像素占比等同于四周纸边，也不要未经真实样图回测设定全页留白下限。
2. **独立看图**：默认后端 `ark_coding_plan`，模型固定为 Coding Plan 的 `deepseek-v4.1-flash`（代码里 `reviewer.default_model()` 返回当前后端实际型号；`SANSHENG_IMAGE_QA_MODEL` / `DEFAULT_MODEL` 只对显式选择的 `claude_cli` 后端生效，对默认后端没有作用）。发送原图及实际缩略/裁切预览，逐条回答合同与图中文字。需要 `ARK_CODING_PLAN_BASE_URL` / `ARK_CODING_PLAN_API_KEY`；缺配置、鉴权失败、限流、空响应、截断或型号不符时停止，不转其它套餐、按量或 Claude。格式不全保留原图，不自动重生。也可用 `SANSHENG_IMAGE_QA_BACKEND` 显式改用 `claude_cli`（本机已登录的 Claude Code）或 `ark_agent_plan`，见 [backends.md](backends.md)「独立复核后端」；默认后端失败时不会自动切换。
   - **多次独立采样**：看图是概率性的（同一张图曾一次通过、一次不通过，通过的那次还幻觉出不存在的影字），所以每张图独立看 N 次，`SANSHENG_IMAGE_QA_SAMPLES` 设次数，默认 3，最小 1（写错报错，不悄悄用默认）。N>1 时每次带一点采样温度（`SANSHENG_IMAGE_QA_TEMPERATURE`，默认 0.3，仅 `coding_plan.request` 支持 `temperature` 时才传），否则 N 次近似同一次。
   - **聚合规则 `majority_after_escalation`（分歧加看、多数决）**：默认看 3 次；所有判定项（必须看到、不许看到、内容分项、逐条要点、分镜、缩略、方形裁切）3 次一致就直接定，任何一项有分歧就再独立看 2 次（`SANSHENG_IMAGE_QA_ESCALATE`，默认 2，0 关闭），每项按全部采样多数决，平票判失败；少数意见与各次原始回答都留在报告的 `_samples` 与 `_aggregation.disagreements`。文字则每次采样的逐字转录都要与应有文字比对，任何一次对不上都算（问题前标「采样k：」）。合同的「未请求的文字或水印」只把文字部分交给逐字比对，另加一条由看图判定的「水印、logo、签名或印章等未请求的标记」；无字档转录出任何一个字即失败。为什么不是「任一次失败即失败」：真实看图里单次采样约有两三成概率在某一条上看错（实测把明摆着的代码文件图标说成没有），合格图三次里约一半会被卡；纯 3 次多数又让漏看真缺陷的概率偏高。分歧时加看到 5 次，两类错误都压到约 5%。
   - **留痕**：聚合结论形状与单次相同（`_review_schema: 2`），另含 `_samples`（每次完整原始回答）、`_aggregation`（规则、次数、`disagreements` 分歧项、`contradictions` 自相矛盾记录）；失败项的 `why` 保留所有判失败那几次的理由并注明几次失败，`triage.sample_disagreements` 同步给出分歧。任何一次采样漏答/格式无效都停下，不丢弃、不自动重试，已完整的采样记在 `_completed_samples`。
3. **文字逐字比对**：拿抄录和应有文字比对，缺字、错字、多写都算不合格。原生出字档忽略标点与空白；位图叠字档逐条精确比对（只忽略每条首尾空白，命令内部的空格、连字符和斜杠都必须正确）。本不该有字的图出现了字也算不合格。提示词会逐条列出「本图已请求的文字」（含品牌名、徽章字），模型不得把它们当成未请求；合同里逐字为「未请求的文字或水印」的那一条只作参考（`triage.advisory`），多写/漏写以逐字比对为准，不再由模型单独定失败。其余禁止条目仍由模型判定。
`points` 只写最终画面可观察的内容。尺寸、RGBA、真实透明通道和执行记录由文件检查及运行记录证明，不要求看图员从画面推断这些属性。透明图预览需按 alpha 叠到白底、深色底等实际背景；不能直接丢弃 alpha 后把隐藏 RGB 当成可见晕边。`sheet` 的对照、缩略和矩阵预览叠到白底，不改源 PNG；预览合格不能代替透明格式检查。

4. **内容事实**：批量执行时把配图清单的 `subject`、`relations`、`inventory`、`points` 和 `panels` 交给看图员；单张 `qa` 加 `--manifest 清单.json` 时做同样核对。`points` 是要表达的**意思**，不自动成为图中文字：逐条只判含义是否通过图形、图标、位置连线或已请求文字传达，条件、否定、数字、单位的含义缺失或相反才失败；不要求把要点原句逐字写在图上，精确字样只由 `text.items` 判定。`points` 只进逐条 `point_match`，不再并入 `content_match`（避免同一条要点重复计罚），也不能只用总体 `content_match` 放行。

内容事实总述（`subject` / `relations` / `inventory`）拆成分项，模型在 `content_match.parts` 里逐项回答；某分项判失败必须在 `failed_clause` 里原样摘出要求中未满足的具体子句，脚本校验该子句确实出现在要求原文里——引用不到、或整体 `ok` 与分项不一致（例如写「这一禁止性要求满足」却整体 false）时，不当作确认的失败，标「待复核」（`triage.next_action = complete_review`，仍不通过、不放行）。校验用的是原文子串，不靠关键词猜测。历史/手工结论没有 `parts` 时仍按旧口径读取。`comic-4panel` 在计划、编译及带清单的单张验收入口，先检查恰有 4 格非空 `panels` 和非空 `relations`；缺项直接拒绝。同一关键物件跨格延续时，在 `relations` 或后格 `panels` 明写身份与状态：例如第 4 格吃的是第 3 格同一只塌陷、无装饰的蛋糕，不允许突然换成完整的草莓奶油蛋糕；“照样吃”之类的暗示不足以可靠验收。四格等分镜必须按从左到右、从上到下逐格回答，漏格或某格与要求冲突即不合格。无字画面不要求证明精确地名，但可见的地域、时代、动作线索必须相容；不能拿后续路线图替某格补足画面。画风与文字全过，但故事事实不符或结论缺失，整张仍不合格；`deliverables.json` 的 `ready` 保持 `false`。旧版缺少逐条或逐格结论的缓存会在续跑时重新看图，不重出原图。维护者自检与独立复核分别记录，不互相冒充。
5. **实际缩略尺寸**：`wechat-cover-square` 在批量或单张 `qa --format wechat-cover-square` 时，从导出图生成 46×46 的 `*.thumb-46.png`，看图员必须读取这张预览并单独回答主体与主题能否辨认。只有大图合格、缩略后成了小色点时仍拒绝交付。旧版只有大图结论的批量缓存会重看，不重出图；缩略图是验收过程件，不是交付图。
6. **居中方形裁切**：`wechat-cover-head`、`xhs-cover`、`xhs-carousel` 的最终导出图另取实际居中方形。看图员必须读取方形图，单独回答标题、主体、题目要求的图形标记和承载信息的次要元素是否完整、与边缘是否有余量；被截断或贴边看不完整即不合格。批量缓存缺少 `square_crop` 结论时重看图，不重生图；单张 `qa --format` 生成 `*.qa-square.png` 后检查。
   S02@r3 另设 `qa.center_square_margin_min: 0.15`：正式 `qa` 对实际居中方图的高对比内容量测四边留白，低于阈值即拒绝，即使看图员主观判「有余量」也不能放行。此量测只适用于该深底样式，不能替代文字、内容和画风看图。

### 任务单与画风合同冲突的优先级

本次任务单（内容计划分项、逐条要点、分镜；**不含**已请求文字）里**显式**写出的要求或禁止，优先于画风合同的「必须看到」条目；「不许看到」条目出现即失败，不能以冲突豁免（真冲突就改任务单或换画风）。例如合同要求「半隐英文影字」而任务单明确写了 never ghost letters，同一张图必有一项不过——此时模型在该条里加 `conflict={task_quote, reason}`：`task_quote` 必须是从任务单**逐字**摘出的原句（至少 6 个有效字符），脚本校验它确实出现在任务单文本里（合同条款本身不算任务单）；校验通过才把该条记为不适用，并在 `triage.conflicts` 写出条目、原句与原因；校验不过（伪造、过短、出处不对）则声明作废，`triage.conflicts_rejected` 记录，该条按原判定计。多次采样时，每一次判失败的采样都须各自提出成立的冲突声明（逐条核对原文），少数采样的声明不能盖掉另一次采样判出的缺陷。声明只能豁免与任务单原文明确冲突的条目，任务单没提到某条不算冲突；不适用条目超过必须项的三分之一仍交人复核。

技术分栏里同一主体的正侧背面或局部辅助视图按同一身份计数；出现不同身份的额外人物仍须拒收。人物自身的左／右不按观者的画面左／右替代；看不清方向时报告无法核实。该说明只澄清看图口径，不改变题目的主体、数量或空间关系要求。

合同里 `qa.when_text` 列出的条目只在图里有字时检查（例如「标题是黏土字」对无字的人物图不适用）。
英文 ghost 层的“不得大于主标题”按字高和视觉权重判断，不按整行宽度；低不透明度的白字在深底上看起来会是灰色。真正字高过大、对比抢过中文标题或缩略图先看到英文时仍拒收。这沿用写作技能原配方的字高定义，不改私有 S02 合同与来源逐字对照。

## 命令

```bash
python3 scripts/sb.py qa 图.png --style C31 --text "番茄工作法|专注25分钟" --format xhs-carousel --report 报告.json
python3 scripts/sb.py qa 图.png --style C31 --manifest 本张图的清单.json --report 报告.json
python3 scripts/sb.py sheet 定妆图.png 图2.png 图3.png -o 对照.png     # 一致性对照网格
python3 scripts/sb.py sheet 封面.png --thumbs -o 缩略.png               # 46/66/128 像素可辨认
python3 scripts/sb.py qa-contrast 问题图.png 候选图.png --defect-file 禁止特征.txt --report 对照.json
```

退出码 1 = 当前证据未通过，不能直接解释为必须重新生图。报告中的 `triage.next_action` 区分 `complete_review`（漏项/格式错误）、`collect_evidence`（看不清）、`diagnose_before_repair`（确认失败，先诊断）和 `accept`。这些提示不放宽 `passed`；缺证据仍不可采用。
单张验收若没有清单，只检画风、像素和明确给出的文字；手工结论里若提供了 `content_match`，它同样必须有效且为真。需要证明画面符合原题时传 `--manifest`，不能用未核内容事实的绿灯充作整张图合格。

叠字版式可在合同的 `qa.overlay_layout` 填 `headline_min_font_px_ratio` 和／或 `subtitle_max_lines`。正式单张验收须带清单；批量验收会传入同一清单。前者只用叠字字号相对最终画布高度排除明显过小的标题，后者按换行符限制副标题行数。两项都是必要条件，仍要实际看图核对字高、层级与方图裁切。S02 的旧切图重排试稿曾在 383 px 高封面使用 36 px 标题及双行副标题，居中方图边距合格却不符合同；该试稿不可用作准入证据。

## 边界缺陷的双图对照

逐张看图都判绿、但维护者看到明确材质或构图差异时，先把**一个可观察的禁止特征**写进 UTF-8 `禁止特征.txt`，用 `qa-contrast --defect-file` 比较已知问题图与返修候选。`--criterion-file` 则只接受希望画面满足的正向特征；两种写法的缺陷真假方向相反，不可混用。两次请求不透露哪个是旧图，并交换 A/B 顺序；只有两次都指出旧图有该缺陷、候选没有且选候选时，才返回 `candidate_better`。位置偏好、两张都过、两张都不过或结论分歧均为 `inconclusive`，退出码 1。报告含原图 SHA-256 和两次原始回答；已有报告不会被覆盖。此入口当前只走已配置的 Ark Agent Plan 独立看图套餐。

如果缺陷只在局部，先用**相同像素区域**裁两张图，再把裁图送入对照；同时保留全图与裁图，记录裁切框。2026-09-27 C58 雨后石路诊断中，全图对照因一轮把候选看成过干而给 `inconclusive`，同框路面裁图两次换序才稳定指出旧图亮面过多。裁图对照只能说明该局部相对改善，仍须对最终全图做内容、画风、文字、像素验收；不能把 `candidate_better` 写成正式样式准入。

整图逐条验收也可能漏掉局部材质缺陷。遇到已知反例仍被整图判绿时，可把**同一条可观察判据**分别用于反例区域和候选区域的独立裁图看图；先确认已知反例被拒，再确认候选通过，保存原图、裁切框、判据和原始回答。2026-09-27 C58 的两张镜面湿路裁图在这一步均被拒，返修后的哑光路面裁图通过；对应整图此前有漏判。此检查只补足局部诊断，裁切可能隐藏主体、文字和空间关系，整图仍须另行验收。同一判据若在其他已知反例上漏判，不得升为自动硬闸或据此准入样式。

维护者可对**已裁好的局部图**运行 `python3 scripts/sb.py qa-focus 局部.png --original 整图.png --criterion-file 判据.txt --report 局部复核.json`。命令对同一局部做两次无历史上下文的独立看图；两次都明确回答禁止特征不存在才返回 0，任何出现、漏答或分歧返回 1。报告保存局部与整图哈希及原始回答，已有报告不覆盖。裁图须保留裁切框和原图，先用同一判据跑已知反例，确保它返回 1，再检查候选。`qa-focus` 只检查局部缺陷，不检查整图内容、文字、像素与风格矩阵。

## 没有可用独立看图入口的宿主（Codex 等）

用 manual 模式：宿主模型按 `stylebook.qa.review_prompt(...)` 生成的问题自己看图，写出同样结构的 JSON，再用 `--review-json 结论.json` 交给脚本判定。
`must_see` 每条须有布尔 `ok` 与非空 `why`，`must_not_see` 每条须有布尔 `present` 与非空 `why`；即使图里没有文字，也要写 `"transcribed_text": []`。缺字段、重复条目或无依据的结论会被拒绝，不能把未知当作「未出现」。

若 Claude CLI 未登录或订阅访问被拒，或 Ark Agent Plan 的地址、Key、额度不可用，批量独立看图会在首张对应错误后停下，保留已出的图片与结论。此时可用 manual 模式继续单图自检；维护者自行看图的记录不能充作准入所需的两次独立复核。

批量输出的 `deliverables.json` 和 `report.md` 记录每张图的 `review_source`。默认 Coding Plan 标为 `ark_coding_plan`；历史 Claude CLI 标为 `claude_cli`，Agent Plan 标为 `ark_agent_plan`；注入其他看图结果时由调用者标明来源，未标明则为 `provided_unspecified`；历史缓存缺来源标为 `legacy_unknown`。`ready: true` 只表示该来源下的检查已通过，不能单独证明独立复核或样式准入。续跑沿用缓存结论时保留原来源，不用本次传入的来源覆盖。

## 色板偏差报告（只报告）

`python3 scripts/sb.py qa-palette <图> --family macaron`（或 `--hex #1F6F8B …`）统计成图主要颜色离色板多远：只有饱和、面积 ≥ 5% 且离色板 OKLab 距离 ×100 超过 10 的颜色才算偏差，纸色墨色这类中性色不计；偏差面积超过 15% 时 `flag` 为真。结果固定写 `mode: report_only`，不拒绝任何图。回测（2026-10-05，54 张已知色系的图对 18 个色板）：区分力 AUC 约 0.71；正确色板误报约 11%，错误色板只检出约 48%。结论：能提示明显跑偏，但会漏掉一半，不能升级成闸门，看图验收不可省。## 串味报告（只报告）

`python3 scripts/sb.py qa-leak <成图> <参考图>`：取参考图里纹理最丰富的 30 块，在成图里做多尺度（0.7–1.4 倍）高通归一化互相关，某块几乎原样出现就 `flag`。纯 numpy，不用模型。回测（2026-10-05）：把参考板的一块人工贴进成图的 24 张样本检出 21 张；20 张真实成图（4 个画风、板与范例）0 误报；报警线 0.80。**它只能发现原样搬运**，发现不了「换了姿势的同一个人物」或重画的同类物件，那类串味仍靠独立看图；人工贴块也不等于真实串味，真实串味样本这次没有（实验里没出现串味），所以检出率只是上限的估计。

## 返修

`overlay` / `hybrid` 的底图可能要求「无字、留白」，最终成图则应有准确文字。若 `content.relations` 写了只适用于底图的指令，在清单另写 `content.final_relations` 描述成图的实际空间关系；生图仍用 `relations`，成品质检用 `final_relations`，而 `subject`、全部 `points` 和逐字文字要求照常检查。`final_relations` 不得省略必要事实或拿来豁免内容错误。

先以原题和正式配方核对 `problems`，不要直接把所有意见转成新增硬约束。每条打回需有原要求、图上位置证据和影响；临时抛光目标不自动成为成品门槛。只接近上限但未超限、或缩略图无法确认，先查原尺寸/局部，不先重生。逐条回答可加 `observation: unverified`，此时仍不通过，但处理方向是补证据。确认后重新保留有绑定的完整结论，不能修改旧报告伪造当时通过。

Coding Plan 看图用本次完整条款的固定标识回答（M1/B1等），消费者将已知标识绑定回原条款，不依赖模型复述长句；未知、重复、原文冲突或漏项仍拒绝，不模糊匹配。单张 `qa --report` 在漏答/无法解析时也保存原响应与原图绑定，标为 `complete_review`；缺完整审核不等于图片错误，不自动重试或重生。保留失败报告，补原条款对应的实际看图证据后另存完整结论。

同一次初审收齐内容、画风、文字、系列、裁切缺陷；疑点单列，优化意见放 `suggestions`。如本轮有局部编辑目标，在审核合同上下文的 `_edit_goals` 列出，回答保存为 `edit_goals`；未完成编辑目标本身不改变原题验收，真正的内容/合同违规照常阻断。`suggestions` 或全局 `overall: pass` 也不能豁免任何硬项。

第一次未通过，下一次调用前留下短诊断：`原要求 → 图上证据 → 根因假设 → 实际改动 → 保持项 → 成功条件`。审核误读就纠正意见；输入遗漏/冲突就修源清单并重编译；原图可用而文字/裁切/比例层错就修装配；确认的局部执行错误用局部编辑，整体构图或画法错误才重画。仅追加“务必”不算纠偏。保持身份只锁身份特征，不锁住需要修复的失败轮廓。

一次针对性修复仍无改善，比较前后图和实际提示词，区分首审漏检与本轮引入的问题。没有新的可检验原因与方法，不再同式调用；将该槽位保留为诊断待办，同时推进独立任务，最后收口，不删场景或假通过。多图共用模板出错时修模板，只复核受影响项目，不重生有效旧图。

`make --prepare` 会生成 `*-execution-card.json`，从实际编译结果展示题面、文字配置、参考职责、硬条目、工具参数及导出尺寸；它是输入检查材料，不是看图通过证据。执行卡不改写提示词、不更改旧 prepared 的摘要。语义冲突由宿主核对，机器检查不能证明内容充分或画风质量。

输入前检须对照完整配方检查职责限制，不仅确认参数齐全。例如C96要求画内织物、木材、植物也有装饰纹理，不能在内容中另写“民俗装饰只留边框”；限制边框不能成为额外流程节点，也不等于禁止画内纹理。同模板有这种冲突，保留原输入，修源清单并重编译，复核受影响旧图；现图仍符合纠正后的完整要求时复用，不因输入文字变化直接重生。

漫画连续性核对同一身份、物件及题面规定的关系。一个空盆在三格分别出现不等于三只盆；原题没有固定坐标时，道具跨时点移动、镜头改变不能单独作为打回理由。若明确要求原地不动或固定左右关系，仍逐格检查；单格多出一颗蛋黄、同一物件变样或关系相反仍须拒绝。明确的完成状态（湿土/浇水壶表示刚浇过水）可与下一动作共存，不强求同时画浇水和走路；状态必须实际可见，不能凭后格补齐前格事实。

## 已知局限

整页漫画的细小物件计数可能漏检，也可能用错误理由拒绝一张确有其他缺陷的图。校准必须同时核对结论和命中的真实缺陷，不能把“错图被拒绝”直接算作正确检出。数量、动作完成状态和关键关系由宿主实际看图复核；整图初筛漏看时，另查局部或逐物件位置证据，不能继续重复同一整图盲审，更不能据模型总判重生。

同一张图重复看图可能得出不同结论。多次采样的目的是让单次看错不决定结论：分歧时加看、按全部采样多数决，分歧项与少数意见留在报告里供诊断；不能在聚合之外靠重跑整轮验收挑出一次通过。首次意见有误时保留原报告，定位条款、图上证据和输入原因；补查只针对已诊断的疑点或新增的实际裁切/局部证据，不进行无原因的同式重审。

报告绑定（`binding`）的判断参数里含合同、方形裁切与缩略图的**绝对路径**（`_path` / `_square_crop_expectation` / `_thumbnail_expectation`），目录移动后旧报告会失效，内容相同的候选放在不同目录也会得到不同绑定。这是已知限制：绑定在 `sb.py` 与写作技能适配器里构造，改成相对路径或内容摘要需同时修改它们（`qa/` 包内无法单独修正）。

正向条款须确认特征实际存在及其位置，不能用“没有淹没主体”证明所需纹样存在。原题或配方明确限定物件范围时，核对背景中的独立实物；表面及边框的装饰纹样不当成额外实物。一般布景豁免不能覆盖明确的范围限定。

独立模型的通过报告也可能漏检。批量授权采用前，用已确认错图和合格图校准对应缺陷；负例仍漏检时，不宣称审图已可靠，相关语义采用由宿主定向核对。输入整理、确定性导出、证据绑定和已采用图的登记仍可交由工作者执行，不重复看图来完成这些机械步骤。
