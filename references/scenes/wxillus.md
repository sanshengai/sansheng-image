# 文章插图（公众号、博客、X Articles）

场景 id `wxillus`。格式 `article-summary`（16:9）、`article-summary-tall`（9:16 竖版）。与写作 Skill 的接口见本页末尾。

先应用 [内容取舍与评审](../editorial-review.md)：读者与沟通目标先于画风默认值；覆盖与字号按本用途验收。

## 目的

替读者概括上下文：读者不看正文也知道这一段说了什么。

## 流程（读全文 → 价值门 → 图型 → 清单 → 确认 → 出图 → 逐字核对）

1. **通读并切段。** 完整读定稿，标出每段的主张、结构信号（顺序词、对举、分类、层级）、数字、专名、引语。
2. **价值门。** 先过 [value-gate](../lib/value-gate.md) 的「不配图条款」，命中就建议整篇不配正文图；否则打分、定张数，淘汰的段落写一句原因。允许零张。
3. **定图型。** 按 [figure-types](../lib/figure-types.md) 的决策流先问「关系类型」。结构图型不成立，才用概念隐喻。同一篇至少一半换形式，不反复用同一个图型。
4. **冻结文字清单。** 按 [text-budget](../lib/text-budget.md) 从原文取字，标来源。数字、专名、引语必须逐字取自原文。
5. **画幅。** 一篇一种画幅；公众号正文用 16:9；竖版 9:16 只用于手机长图和转小红书，不进公众号正文。结构图出横版时纵向图型要改版式。
6. **确认一次。** 给作者一张计划卡（见下），回「好」或改一行就出图（brief 写 `"confirmed": "user"`）；用户说「直接出」或由自动流程调用则跳过（写 `"confirmed": "skipped"`）。无论哪种，计划卡都会存成输出目录的 `plan-card.md`。图上的数字、引语、英文专名必须能在原文找到，算出来的数字写 `derived`，详见 [SKILL.md](../../SKILL.md) 第 1、2 步。首次用某画风、或换画风时，先出 1 张样张。
7. **出图。** 带数字、专名或文字清单超过 8 项的图，用「留白底图 + 程序精确排字」；文字 ≤ 6 个短标签且无数字的概念隐喻，可以让模型直接写字。出图走 `make`，参考图按 [consistency](../consistency.md)。
8. **逐字核对与总览。** 按 [post-checks](../lib/post-checks.md)；出图后给总览图，作者只需点名重做哪几张。

## 计划卡（每张一行）

锚点（插在哪句话之后）· 判断句标题 · 一句命题（这张图不是要画___，而是让读者看懂___）· 任务 · 图型（附一个备选）· 横或竖 · 图上全部文字（标来源）· 为什么值得画 · 需要作者核对的数字与引语。表末列「被否决候选」。

## 落到文章计划 v3

正式计划的格式和独立复核见 [planning.md](../planning.md)。本页的「被否决候选」就是计划里 `coverage` 中 `decision` 为 `text_sufficient` 或 `existing_visual` 的项，`why` 写淘汰原因；入围项是 `decision: image`，`image_ids` 对应计划卡的行。价值门打分结果写进各项的 `why`。

## 做法要点

- 图上不写引导语（「一张图看懂」「如下图」「往下滑」），图本身就是内容。
- 判断句标题写结论，不写话题；标签只用原文里的真实术语和数字；隐喻画底层概念，不画字面物体。
- 一张图只承担一个命题；说不成「不是……而是……」的一句话就拆图。
- 同篇推特单图：同一结论再出一张 16:9，大标题、正好 3 个要点、右下角品牌标识；它会脱离正文单独传播。
- 图型不确定时（对比和清单都说得通），不烧额度，在计划卡里给两个图型的文字线框让作者挑。

## 与写作 Skill 的接口

写作侧交：定稿、平台、画风码、作者提示（可选）、原文里的数字与引语清单。出图侧回：计划卡、图片文件、出图记录，以及「可图解性诊断」（哪几段写得太抽象画不出来，反馈给写作侧）。作者提示的写法：一行写这一段想让读者带走的判断，一行写想要的图型（可选）。
