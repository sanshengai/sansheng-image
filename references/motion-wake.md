# 成熟动态方法：使用外部 lemo-wake

用户明确要动态，且已有认可的上游方法或相近案例时走本页。静态仍为默认；已采用静态图直接复用，不为进入动态流程重画。

## 普通请求的执行入口

用户可以直接说：

> 给这篇文章配图，沿用我已经采用的静态图，把适合的部分做成动态版。

Agent负责从这句话走到成品，不要求用户先准备HTML工程或填写内部参数：

1. 读原文与已采用的图，按 [审美判断的选图表](motion-taste.md#先筛图片与动机) 先筛选，确定动态的用途。翻阅整组图片属于导览；解释步骤需要能看清步骤的变化；人物动作需要主体真正行动。按实际用途命名，不用“会动”笼统代替。
2. 按下文读取外部上游、选择相近完整案例，检查素材是否够用。沿用已确认画风、色系和原图；缺少完整部件时由Agent补齐或调整表达，不能拿残缺切片硬做。没有动态收益时说明判断，保留静态。
3. 由Agent准备素材、导演说明和自包含工程，再执行下文复跑与导出。工程设计是制作的一部分，复跑脚本不是自动理解图片的转换器。
4. 完整播放自检后交付原图、动态文件与源工程，注明用途及实际未验的平台。只修明确缺陷，不因进入动态流程把已采用静态组全部重做。

已有授权和偏好足以执行时直接继续；不要为画幅、路径、内部时刻逐项追问。依赖缺失时报告缺少的工具和下一步，不把准备好工程或生成计划说成已交付成片。

## 先读上游，再选适合这张图的动作

依赖来自 [Lemomo / lemo-wake](https://github.com/lemomo-ai/lemo-wake)，独立保存或安装，不随本包复制。先定位它的 `skills/wake/SKILL.md`（下文 `$WAKE` 指该目录），再读它的 `references/taste.md` 及与本题有关的实例。缺少上游依赖时说明缺项，不悄悄回退到旧的局部晃动效果。

本地已验证的上游源码版本是 `f17890701dd3c782fe0e0a992fb5c2c12063194d`；别的版本先核对实际命令。上游完整工程、素材和各作品源码的可用性不同，不能把画廊上的每支片子都说成有现成模板。

先看真实素材和可完整取得的部件，再决定编排：

- 阅读/排版类可借鉴已验证的开书、翻页和纸带编排；适配时保留成熟节奏，重核自己的标题、图片和最终版面。
- 物件展示、拆解和组合，先按上游方法取得完整物件与补好的背景，再编排主要物件的行动。
- 文章中的步骤、关系、对比，可设计展开或重组；变化要对应原文，不能仅把标签逐个淡入。

这些是选型提示，不是固定分类或每类必做的配额。人物编织不能只动毛球，折叠结构不能拿残缺切片硬变形；素材条件不成立就调整表达方案。不能把所有题材都套成翻书。

## 准备工程

按上游工作流准备一个包含 `index.html`、本地字体及素材的 `src/`。使用上游现有工程时保留来源与变更；基于其规则新编排时如实说明。输出画幅是设计选择，改画幅需重新布局。

工程遵守上游 `window.CFG` / `window.render(t)` / `window.READY` 约定。同一 `t` 可重复渲染；图片和字体加载完成再 READY。现有 `sb.py animate` 的 HyperFrames manifest 与本格式不同，不相互冒充，也不把一个强塞给另一个渲染器。

上述已验证版本的配置字段为 `window.CFG = { outW: 1280, outH: 720, fps: 30, dur: 7.2 }`，`dur` 的单位是秒。先设 `window.READY = false`，所有本地图片和字体加载完成后再赋值为布尔值 `true`；不要把 Promise 本身赋给 READY。`window.render(t)` 接收秒数并绘制该时刻的完整状态。替换上游版本时重新核对这些字段，不用其他工具的 `width` / `height` / `duration` 猜测接口。

先用上游 `render.mjs ... stills` 看动作起中末和极值；主动作、裁切、遮挡与文字通过自检后再导出。导演说明记录用途、原图、主动作及理由、素材完整性、保留项、准确文字、关键时刻与动作极值、首尾状态、来源及停止制作的条件。说明哪些是借用的方法、哪些是自行编排，不把上游的展厅分类直接变成客户必须选择的流程。

## 从本 Skill 复跑与导出

本包只提供自写的调用脚本，不包含上游动作代码，不自动安装第三方依赖。需要 Node.js、上游的 Playwright/浏览器环境、uv、ffmpeg 和 ffprobe；上游 Python 脚本的环境由其 `uv run --script` 处理。先按上游环境检查完成配置。

### 首次配置

由Agent先定位已有上游目录，避免重复下载。尚未取得上游时，从上述仓库单独获取，并按本页已验证的commit核对版本；不要用作者本机路径作为安装要求。`$WAKE` 指向其中的 `skills/wake`。

已验证版本的 `scripts/package.json` 声明 `playwright-core`，Node依赖装在上游脚本目录：

```sh
npm install --prefix "$WAKE/scripts"
```

上游渲染器会依次寻找 `CHROME` 环境变量、Playwright缓存和系统Chrome/Chromium；已有可用浏览器时无需另装一份。需要指定时，把 `CHROME` 设为实际浏览器可执行文件。缺浏览器则按上游说明配置，不用 `animate doctor` 的结果代替本路径检查。

确认 `node --version`、`uv --version`、`ffmpeg -version`、`ffprobe -version` 能运行。首次 `uv run --script` 可能联网取得上游声明的Python依赖；后续使用缓存。`--plan` 只检查输入及基本命令是否存在，不启动浏览器，也不证明Node包、浏览器和Python依赖都已就绪；完整导出成功才是该环境的实际验证。

`$WAKE` 由执行者根据实际安装位置填写，`$SRC` 是已准备好的自包含工程；不需要用户选择内部参数。先预演：

```sh
python3 scripts/replay_wake.py "$SRC" --wake-skill "$WAKE" --out "$NEW_OUT" --plan
```

确认后去掉 `--plan`，实际调用上游渲染、编码和 QA：

```sh
python3 scripts/replay_wake.py "$SRC" --wake-skill "$WAKE" --out "$NEW_OUT"
```

已经确认适合纸张回落的工程可加 `--reset paper --hold 0.7 --transition 0.6`；这不是所有作品的默认动作。`--stills 0 1.8 2.6 4.8` 可指定审片时刻，时间必须位于本工程时长内。默认只抽第0帧，不代表已经做过完整审片。

脚本把源工程复制到全新输出目录，然后运行上游原工具；不覆盖原工程或旧成品。得到 `motion.mp4`、`motion.gif`、`motion.webp`、`qa.json`、`replay.json` 和逐步日志；失败则保留已做部分与失败步骤。它只复跑**已经准备好的工程**，不会自动把任意静态图变成好看的动态。

## 交付与边界

完整看至少两轮，检查主体真正行动、部件完整、文字正确、节奏和收束；关键帧不能代替完整播放。机器报告通过只说明被检查的技术项，用户采用和平台可用另记。保留源图与最终定格，重新排版的海报要标明是改编，不能声称原图原画风已复现。

上游仓的代码/文档标注 CC BY-NC 4.0，按具体文件核对，并保留作者、版本及修改说明。本包原有许可不覆盖外部上游代码。公开演示、成片、素材及再分发分别核对来源和授权，不因外部调用就自动获得额外授权；授权未明确的研究工程留在本地。平台上传兼容性未经实际测试不作承诺。

现阶段证据：KADO原动作代码实跑获得用户认可；自有题材适配仍逐支审片。认可一个动作案例不证明所有画风、任意素材或全部平台都已可用。

## 本轮原创工艺试验的可复用判断

2026-10-18 已用自有素材实际导出套印成画、信息交接及夜色显影三种候选。它们是制作实证，尚未获用户采用，不列为精选模板。

- **套印成画：** 先将像素分配到互不重叠的色版，核对重新合成后能恢复原图，再设计落色、套准和完整画面停留。不要先分层后发现原图拼不回来。
- **信息交接：** 用同一张信息纸跨步骤传递，检查动作中段的对象归属、标签遮挡和阅读时间；步骤文字与原文保持一致。
- **氛围显影：** 光路与夜色可以构成视觉因果，但显影好看仍需判断动态收益。主体没有实际行为时，不把它概括成任意故事图的成功方法。

复用的是判断与素材准备办法；新的题材、代码和输出仍需完成工程准备、关键帧、连续播放和用户审片。
