# 动态版：从原图到审片交付

用户明确要“做成动的、动图、短视频版”时才进入本页。普通配图继续静态流程；已采用的静态图直接复用。用户仍只使用叁笙生图，当前 Agent 负责读图、导演、编写动作和审片，`sb.py animate wake` 负责工程、上游工具、预览、渲染和记录。它不是一键图生视频模型。

先看 [历次实验与可复用判断](motion-lessons.md)。工程字段及中断恢复见 [动态工程约定](motion-project.md)。已有 HyperFrames 工程继续走 [兼容入口](motion-scenes.md)；已有 wake 工程可继续用 `scripts/replay_wake.py`。不要求用户迁移已采用作品。

## 承接静态配图

先读文章、图片放置位置和已采用的原图，沿用已确认的画风、色系、事实与准确文字。判断这张图为什么值得动，再选表达方式：

- 氛围：灯逐渐亮起、光沿真实路径变化、风影响可活动的部分。保护主体、曝光和原图的层次，不能靠整图变黑或反复缩放制造差异。
- 叙事：动作由场景触发，有响应和结果。物件需要完整边缘、支撑与遮挡关系；不能把断腿人物、半朵花、带着地面的帐篷弹入画面。
- 解说：逐步展开因果、关系或对比，每一步对应原文且留够阅读时间。
- 材质：照片、书页、纸张、印刷等可展开、翻转和归位，变化应服务于展示内容。不能把所有题材都套成翻书。

题材分类不等于动作模板。静态图漂亮不等于素材适合拆动；没有动态收益，或无法得到可信的完整部件，就说明原因、保留静态。需要人物或生物连续转身、肢体变形时，刚性切片不能代替真正动作；调整表达或进入既有视频制作流程，不硬做。

文章插图默认输出 1280×720；小红书场景默认沿用原图画幅。用户明确尺寸优先。竖向 9:16 原图便于和横向成片对照，但不是强制输入规格。更换输出比例要重新构图，不直接拉伸。可从静态 `brief.json` 继承场景、画风、色系、系列和图片条目，绑定原文校验值；不要另写一套相互矛盾的配图需求。

## 首次启用可选运行环境

使用 [Lemomo / lemo-wake](https://github.com/lemomo-ai/lemo-wake) 的固定版本 `f17890701dd3c782fe0e0a992fb5c2c12063194d`。上游独立保存在配置目录的运行环境中，不加入任何 Agent 的 Skill 扫描入口。用户不需要再安装第二个生图 Skill。

由 Agent 检查现有环境后执行一次：

```sh
python3 scripts/sb.py animate wake setup --install
python3 scripts/sb.py animate wake doctor
```

已有相同版本时可用 `setup --wake-skill <其 skills/wake 目录> --node-deps`。复用已有模型时加 `--models-dir <实际模型目录>`，需要指定浏览器时加 `--chrome <实际可执行文件>`。不要猜作者本机路径。`SANSHENG_IMAGE_CONFIG_DIR` 可指定独立配置目录；`setup --disable` 关闭本模块。

安装器取得固定版本、核对源码指纹，安装其 Node 依赖并保留原许可；不安装系统工具、不批量下载模型。需要 Node.js 18+、uv、ffmpeg、ffprobe 与可用 Chrome/Chromium；不需要 HyperFrames。上游 Python 依赖由 `uv run --script` 管理。所需模型按实际分件、修补任务使用上游 `models` 工具检查和取得，模型目录全程保持一致。doctor 会实际启动浏览器；doctor 通过不代表模型齐全或成片好看。没有动态请求时不检查或下载本模块的依赖。

## 看图、备料，再定完整动作

先查看原图。初始化后读取返回的上游 `SKILL.md`、`references/taste.md`，以及与本图有关的 `types/` 手册和完整案例。上游强调可见变化，但动作幅度须服从本图的用途与用户反馈；不能为了符合“大动作”而破坏物理关系。

```sh
python3 scripts/sb.py animate wake init <原图> --out <全新工程目录> --purpose "本图在文章中承担的具体作用" --article <原文>
```

复用静态需求时改用或补充 `--brief <静态工程/prepared.json> --item <图片 id>`；优先使用已经采用的 `prepared.json`，直接继承实际编译后的画风、色系、文字与插入位置，不再解析一次当前偏好。也支持原生 `brief.json`（`source` 是原文路径），通过既有静态编译器解析 `sb2` 码后再继承，不自造另一种需求格式。已有明确规格可加 `--size 1280x720 --duration 6 --fps 30`。命令保留原始输入，建立 `src/` 和待填写的 `director.json`。这是开始制作，不是生成完成。

工具统一从本入口调用，例如：

```sh
python3 scripts/sb.py animate wake tool <工程> segment src/assets/source.png --out src/assets/mask.png --model sam --point <X,Y> --cutout src/assets/actor.png
python3 scripts/sb.py animate wake tool <工程> inpaint src/assets/source.png src/assets/mask.png --out src/assets/background.png --engine lama
```

示例路径需按 `init` 实际生成的文件名填写。坐标以归一化后的源图为准，不用原始大图坐标硬套。其他工具为 `depth`、`sheet`、`measure`、`models`，具体参数读取该固定版本的帮助；调用及退出码保留在 `tool-runs/`。

先看实际分件、遮罩和补洞结果：头脚、花茎、轮轴、托盘是否完整；隐藏面能否承担翻转；移动后背景是否补好；接触、支撑和前后遮挡是否成立。记录实测结果后再确定动作。盘子必须先承接食物，门必须先打开，车轮必须绕真实轴心运动。

确需补料时可调用本 Skill 既有静态生图能力，补完整部件、隐藏面或背景，并保持画风和色系。记录生成、分割、修补的来源及修改；这是融合扩展，不冒称原版“不生图”的同条件实验。不要通过另一套宿主或另装 Skill 绕开现有生图入口。连续两轮仍修不好同一个结构问题，就换动作方法或保留静态。

## 导演与工程

填写 `director.json`：是否制作、为什么值得动、保护内容、实际素材及完整性观察、变化与落定、极值审片时刻、循环和限制。`DIRECTOR.md` 可记更完整的判断与返修。素材清单中的“完整”必须来自实际看图，不能为了通过检查随手填 true。

当前 Agent 在 `src/` 编写确定性动作，使用本地图片与字体。接口为：

```js
window.CFG = { outW: 1280, outH: 720, fps: 30, dur: 6 };
window.READY = false;
// 图片和字体加载完成后设置布尔值 true。
window.render = function (t) { /* t 为秒；每次完整绘制该时刻 */ };
```

循环优先在画面内设计；需要帧级过渡时读取上游 `reset.py --list`，在导演稿中填写 `reset`。不要把每支片子都接同一种转场。参考邻近工程的审片记录，避免重复相同编排；本模块的工程、工具及审片记录代替向上游安装目录写私人历史。

同一 `t` 无论调用顺序如何都应得到同一画面；不要依赖累计位移、实时随机数或上次渲染状态。规格须与 `motion.json` 一致。原始模板不含本图的动作，不能直接当成成品。

## 预览与返修

```sh
python3 scripts/sb.py animate wake preview <工程>
```

命令检查接口、加载错误和重复时刻的确定性，输出素材联系表及时间联系表。由当前 Agent 实际查看这些图和原尺寸关键帧，重点看动作极值、切边、遮挡、文字、曝光与最终落位。审片时刻由动作决定，至少覆盖几个关键状态，不要求固定九帧。此前从官方成片抽取的九帧是研究资料，不是新图片必须自带的分镜。

发现问题先改材料、导演稿或动作代码，再重新预览。源码、输入、字体或导演稿改变后，旧预览和旧审片不能沿用。检查只能确认材料和记录齐全、输入一致，不能自动证明抠图自然或审美合格。

## 渲染、连续播放与交付

```sh
python3 scripts/sb.py animate wake render <工程>
```

从与当前工程匹配的预览进入渲染，得到 MP4、GIF、动画 WebP、QA、源工程和 `review.html`。审阅页将完整原图与横向动态紧邻对照，默认静音自动循环，保留播放控制并尊重减少动态设置。每次生成新候选，不覆盖旧片。

连续看至少两轮，检查动态收益、主体完整、因果、构图、文字和循环；不能只看联系表。将实际观察写入成片目录的审片模板，再执行：

```sh
python3 scripts/sb.py animate wake review <工程> --render <该次 renders 目录> --assessment <已填写 JSON>
python3 scripts/sb.py animate wake status <工程>
```

有问题记为 `revise`，修后重新预览、渲染和审片；通过制作审片记为候选，不替用户记录“已采用”。机器 QA 为空或仍有 FAIL 时不能通过；WARN 需要结合画面实际判断。输出改变后旧审片失效。机器 QA、Agent 观察、用户采用和平台实测分别记录。

公众号交付 GIF 及静态替代图，附回文章的准确插入位置。未经本文件的实际上传测试，平台状态保持 `untested`；旧文件在手机端正常播放的反馈不能覆盖新片。按文章节奏选择合适的一两处动态，不默认把每张配图都替换掉。继续剪辑、配音或改已有视频时遵守本 Skill 的 `sansheng-video` 交接规则。
