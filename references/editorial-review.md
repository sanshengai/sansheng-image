# 从内容取舍到实际成图

## 先明确这张图的工作

先写读者、展示环境、看完应该理解或能做什么，再选视觉关系与画风。用户指定画风或明确喜欢的已有成图优先；否则用途默认作为起点。读者身份不直接决定画风：成人专业内容也可以使用活泼人物、手绘、丰富配色与装饰。只有出现事实误导、遮挡、阅读障碍，或用户明确不喜欢时，才把这些元素列为待改项。

- 封面：传达对象与核心判断，允许不覆盖正文细节。
- 正文插图：解释一个难懂的关系，允许把已有文字留在正文；画面须带来理解增量。
- 小红书：先定全文转述还是选题摘要，再按这个承诺检查遗漏；不能用摘要承诺暗中冒充全文。
- PPT：先定投影演讲、讲读兼顾或独立阅读。按实际环境验字，不拿手机 390 px 阈值统一判所有 PPT。
- 信息图：先判断读者要比较、追踪过程还是理解结构。有年份不等于应选时间线；箭头必须说明顺序、流向或因果，不能把并列观点画成因果。

## 轻量 brief 的内容取舍记录

有原文的任务可增加 `editorial`（纯创作不必造原文）。对文章转图、小红书和信息图，应记录会影响核心理解的保留与舍弃，不要求逐句登记：

```json
"editorial": {
  "audience": "刚开始带项目的成年人",
  "context": "手机文章正文",
  "goal": "理解投入和成果的区别",
  "coverage": [
    {"quote": "原文中的准确引用", "decision": "show", "targets": ["01"], "reason": "本图解释的关键关系"},
    {"quote": "另一个准确引用", "decision": "body", "targets": [], "reason": "细节已有正文，不重复"}
  ]
}
```

`show` 入图，`body` 留在正文，`omit` 本次不呈现。`targets` 引用本次图片 id。程序检查原文引用、去向及理由，读者/环境/目标进入编译提示词，取舍进入计划卡。它不自动找出所有核心观点，也不判定压缩后语义正确；宿主仍须核对限定词、因果、例外与视觉隐喻。字符相似度与 OCR 只能辅助定位，不能算“内容覆盖率”。

## 精确排字：先验底图，再决定落字位置

当前 `make` 的 overlay 会在生成后立即按预设盒子排字，没有中途人工停点。复杂结构不要把这条自动路径说成“已经看过底图”。需要先看底图时复用现有两步命令：

1. 在任务目录冻结最终文字清单及来源；另写底图 brief，`text: []`，在 `visual` 中明确无字主体、关系和预留区域。用 `make --prepare` → 宿主生图 → `--import-results` 留下原图、执行卡与收据。此时只是底图候选。
2. 打开底图看实际物件与留白，记下所看文件的 SHA256、发现的问题和可排字区域；底图关系错误则先返修，不能用文字遮住。按实际最终画幅编写 overlay JSON，只调整位置、字号、断行；不暗改冻结文字。将清单与 overlay 的文字顺序去换行比对。
3. 用 `sb.py export 底图.png --format <目标格式> --overlay 叠字.json -o 新候选.png`。浅底板加 `require_blank`；声明纯色底板时使用 `blank_background` 的现有检查。失败保留证据，不能通过取消检测强行盖字。
4. 看最终成图及目标尺寸预览：逐字、连线对应、层级、裁切、气质均须通过。另存底图摘要、overlay 摘要、最终图摘要和看图结论；初次 make 的收据只证明底图，不覆盖后排字成品。

这是现有命令组成的两步人工流程，尚非 make 的一键暂停/恢复。原生短字无需强制转 overlay；文字超过预算也可以先删减或拆图。

## 对照评审

先区分已证实的错误、可能的歧义与审美建议。指出旧图问题时，给出原文依据和具体读法；不能把“换一种表达”直接说成“内容更好”。图文共同传达准确含义即可，不要求去掉文字后画面还独自解释全部论点；类比也可能增加理解负担。

同源、同读者、同用途、同画幅和同信息任务才能比较方法。修改用户已喜欢的图时，默认保留画风、配色、字体气质和构图，只改变有明确依据的内容。先改一张，不把更换画风与修正内容混在同一轮后归因为内容改善。用户明确要求探索新方向时才放宽这些保留项。

新图须同时检查内容和视觉吸引力。更规整、字更大、装饰更少均不自动等于更好；用户否定的新样保留为失败证据，不写入默认偏好或正式样图库。
