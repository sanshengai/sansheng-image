# 一条留言怎样走完

本例为叁笙原创工程，基于 AI 素材制作。Claude Opus 5.5 交付首稿后，当前 Agent 做了实际渲染、播放审片与定向返修；代码不是未经修改的 API 原样输出。

# 导演说明 · B2 同一条留言经过真实处理（第二版）

## 舞台与版式
- 完整使用 `stage-empty.png`，按宽度等比缩放（0.7656），整体下移 70px，没有拉伸。底部被裁掉的部分只有空白地面，人物和物件都完整保留。图片上沿用 50px 渐变和背景色衔接。
- 顶部是 48px 标题“一条留言怎样走完”，下方是 36px 当前阶段名。工单卡尺寸 600×180，内容只有三行：原文（30px）、建议类别（胶囊 32px）、状态（胶囊 32px，核对项 26px）。卡片底边在 y=304，不会遮住机器人头部、拱门主体或女生头部。
- 底部的限制说明用 26px 一行，第 8.5 秒起出现。

## 时间线（16 秒，24fps）
| 时间 | 观众看到的画面 |
|---|---|
| 0–1.0 | 画面从空舞台开始。信封淡入，从上方落进左侧托盘，落地时有一下小回弹，托盘亮起柔光。阶段名：①收到原留言。 |
| 1.0–2.2 | 绿色心形封口向上翻开，工单卡从信封上方向上展开，用虚线系在信封上。卡上显示原文，状态为“新留言”。 |
| 2.6–3.2 | 阶段名换成②。三个碗上方错位出现 32px 标签“客房 / 维修 / 人工处理”，每个标签用虚线连到自己的碗。 |
| 3.2–4.8 | 信封沿弧线落进“维修”碗，碗沿前景挡住信封下半部分。 |
| 4.6–5.0 | 碗上的“维修”变成实心绿色并上浮，另外两个标签变淡；卡上建议类别变成“维修”，信封左下角贴上“维修”小签。状态变为“待核对”。 |
| 6.0–8.0 | 阶段名换成③。信封移进拱门洞口，略微缩小表示有纵深，门洞绿环的下沿画在信封前面。 |
| 8.0–9.4 | 状态为“核对中”，扫描线扫过信封。“字段齐全”和“类别在范围内”两项依次打勾，信封盖上一个小核对印。底部出现限制说明。 |
| 9.4–11.0 | 信封飞向右侧收件托盘，途中封口合上，最后落进托盘，托盘前沿挡住信封底边。 |
| 11.0–15.2 | 阶段名换成④。状态变成暖棕色“待确认”，信封上也贴出“待确认”标签。这一段静止约 4 秒，留给观众读工单。 |
| 15.2–16.0 | 工单卡收回，信封、标签、碗标签和底部说明一起淡出，阶段名回到①。第 16 秒的画面和第 0 秒相同（空舞台加标题），循环时不硬跳、不闪白。 |

## 同一对象怎样保持身份
- 全片只有一只信封，位置只来自 `state(t).pos`，各段之间是连续弧线。收尾时是这只信封原地淡出，不做交叉淡化，所以任何一帧里都不会同时出现两只信封。
- 工单卡的位置由信封坐标推出，并一直用虚线系在信封上。原文从展开起一直显示到收尾。类别和状态在原地变化，不整张换卡。
- 封口开合用连续值 `open` 控制：收到时打开，送去人工前合上。信封上的类别小签、核对印和“待确认”标签一路累积，不会中途消失。

## 状态如何绑定文字和高亮
- 碗上的高亮、卡片里的类别胶囊、信封上的小签读的都是同一个 `s.cat`，名字取自 `CATS[s.cat].name`。
- 阶段名、状态、两个核对勾、底部说明都在同一个 `state(t)` 里算出来。`render(t)` 只依赖传入的绝对时间，可以按任意顺序定位帧。
- 浏览器预览也是调用同一个 `render(时间 % 16)`，没有另外的时间源或状态；webdriver 环境下不跑预览循环。
- 所有胶囊和标签都先 `measureText` 再画底色。只用一个字体 ArticleSerif，不做缩放变形，字重不随帧变化。没有用到随机数。
- `READY` 只在字体和底图都加载完成后才设为 true。

## 措辞
- 类别只写“建议类别”，阶段名写“Jev 在三个预设类别中建议一个”，没有写“判断正确”。
- 核对只写“字段齐全 / 类别在范围内”，底部一行注明它不代表分类正确。
- 最终状态是“待确认”，全片没有出现“已解决”。

## 素材限制
- 底图没有分层，碗沿、门洞绿环下沿和收件托盘前沿都是我手绘的前景遮挡，颜色是按目测取的近似值，近看可能和底图有细微色差，需要在实际渲染里检查。
- 拱门里本来就画着一个对勾，去不掉。我的处理是让光环、扫描线和核对勾只在第 8–9.4 秒出现，用来表示“现在在核对”。
- 机器人和女生是静态的，没有做动作。
- 右侧工单卡的位置被限制在 x≤660，用来避开女生头部；这一点以及上面的遮挡色，都还需要在真实浏览器里审阅确认。


打包素材保留原尺寸，使用 WebP 压缩衍生；与官网原始 PNG 的像素可能略有差别。支点、裁切和时间线对应本图，不可只换图片沿用坐标。技术复跑不继承用户采用或平台上传结论。
