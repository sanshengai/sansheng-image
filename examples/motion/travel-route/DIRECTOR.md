# 沿着海岸，把一天收好

本例为叁笙原创工程，基于 AI 素材制作。Claude Opus 5.5 交付首稿后，当前 Agent 做了实际渲染、播放审片与定向返修；代码不是未经修改的 API 原样输出。

# 导演稿：沿着海岸，把一天收好

## 画面结构
- 1280×720，24fps，13秒。整个横向画面是一张连续的浅蓝地图桌面：上半部分是海，下半部分是米色陆地，有海岸线、等深线、街道细网和两道折痕；右上角放着固定不动的麻绳和铅笔。
- 标题“沿着海岸，把一天收好”只占一行，40px，放在左上，不设左侧巨字栏。
- 三张照片从左到右排列，互不遮挡：车站和小巷的外框宽354px，海边的外框宽404px，是最大的一张。三张都使用统一12px白边，按源图比例等比缩放，没有拉伸。
- 下方一条细虚线路线依次串起起点、车站、小巷、海边。每个站点有一个30px的标签，并有一根虚线引线连到**自己那张**照片底边的中心，引线不会接到别的照片上。

## 源图裁切（白框内侧的纯照片区域）
- 车站：x194,y286,宽558,高344
- 小巷：x189,y700,宽570,高353
- 海边：x173,y1124,宽593,高381

裁切框都从简报给的白框位置向内收约12–14px，只取照片本身，避开原图白边、邻图和桌面。白边由程序统一重新绘制。

## 机制
- 每张照片都是一张沿长边中线对折的相纸。下半张始终贴在桌上；上半张绕中线这条真实转轴转动180°。合拢时，上半张的米色背面盖住下半张；转过90°之后露出照片正面。转动过程中，上半张的投影高度按cos变化，同时有压暗，接触阴影的模糊和偏移也随抬起高度变化。
- 只有一枚车票标记，位置完全由路线弧长L(t)决定，全程不会分裂。已经走过的路线显示为珊瑚色实线，长度与标记位置用的是同一个L。
- 照片的展开程度open_i(t)、标签下划线和站点圈颜色都读取同一个值。标签底块的位置来自measureText，记录在LABEL_LAYOUT里，和绘制用的是同一份数据。
- render(t)是纯函数：时间先对13取模；桌面纹理用固定种子只生成一次，不随帧累积状态。

## 建议抽查的帧
t=0、2.4（车站翻到一半，正好露出背面与正面交界）、3.5、6.0、9.3、10.8、12.3、12.99。

## 真实局限
- 桌面是程序绘制的近似效果：没有使用源图里的地图纹理、花瓶和贝壳；麻绳和铅笔只是简化的示意形状。
- 翻折是在Canvas里用二维纵向缩放模拟的，没有真正的透视梯形，转到接近90°时会显得偏平。
- 裁切坐标是按简报给的白框数值向内收得到的，我没有逐像素核对源图。如果实际白框有几像素偏差，需要调整CARDS里的src数值，确认没有残留白边或切到邻图。
- 地图和路线都是示意，不对应任何真实地理位置或实际旅行路线。
- 可以调用FILM_DIAGNOSTICS(t)，查看当前阶段、标记位置、三张照片的展开值，以及照片、站点、标签和标题的边界。


协调者修订：三张相纸降低到路线附近，照片按真实独立画框完整截取。上盖围绕共用底边铰链在三维空间转动，用透视平面和三角映射实现；替换原先的纵向缩放。保留 API 输出及旧预览。


打包素材保留原尺寸，使用 WebP 压缩衍生；与官网原始 PNG 的像素可能略有差别。支点、裁切和时间线对应本图，不可只换图片沿用坐标。技术复跑不继承用户采用或平台上传结论。
